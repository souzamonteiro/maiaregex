# Independent BRE reference observations

2026-11-02. These observations are not a claim of full POSIX conformance.
The diagnostic `build/bre/system-reference` compares 18,144 ASCII cases and all
10 captures with the macOS system regcomp/regexec. It currently exits nonzero:
82 differences remain in three pattern families. The test has not been removed,
its expected values have not been changed to match the new engine, and it must
not be counted as a passing acceptance gate. All other corpus cases agree after
fixing stale inner captures across a new outer participation.

The separate AST interpreter in scripts/test-bre-model.mjs exhaustively enumerates
finite expression trees without parsing BRE text or reading generated bytecode.
486 authored/seeded trees over all binary inputs of length 0..5 give 30,618
whole-match/capture comparisons against actual own-chain WASM. It includes
repetition, nested/empty/unmatched groups, intervals and references. This is
independent implementation evidence on a finite corpus, not a general proof of
POSIX capture priority or time complexity.

## Cases needing a broader reference decision

1. `\(a*\)\(a*\)\2\1` on `aa`: macOS returns whole [0,0), while the selected
   longest profile has [0,2), group1 [0,1), group2 [1,1). The valid decomposition
   is `a` + empty + empty-reference + `a`-reference. On `aaaa` both match four
   characters, but macOS chooses group1 [0,1) and group2 [1,2); earlier-group
   longest priority instead chooses group1 [0,2), group2 [2,2).
2. `\(\(a*\)b*\)*\2` on `b`: macOS returns whole [0,0), while [0,1) exists:
   outer [0,1), inner [0,0), literal b, followed by the empty reference.
3. `\(a*\)\{0,2\}` on empty text: macOS reports the group unused. The selected
   matcher records an empty participating group [0,0), preferring empty
   participation over nonparticipation at the same whole extent.

The fixed matching/API vectors and AST enumeration preserve these explicit
longest/empty choices; libc discrepancies remain visible. Empty BRE/groups,
UTF-8 scalar ordinal classes and rejected locale/GNU extensions also require
separate portability notes and are not fed to an ASCII shared-profile oracle as
if all dialects agreed. No libc implementation is used by production matching.

Reference interpretation: OpenBSD documents earliest then longest whole match,
earlier/higher-level subgroup priority, and empty participation before no match
in [re_format(7)](https://man.openbsd.org/re_format.7). GNU describes inner captures
being invalidated by a new outer iteration in
[Subexpression complications](https://snapshots.sourceware.org/glibc/trunk/latest/manual/html_node/Subexpression-Complications.html).
These support the stated expectations; an additional independent implementation
and a more general capture-history argument are still desirable before claiming
complete conformance. Never silently change the approved profile to match one
system's behavior.

## Adjudication — extended final corpus

After the overlapping-repeat priority correction (BRE_CAPTURE_SELECTION.md), the
raw comparison covers41,148 cases. Exactly three families differ:31 multiple-
reference cases,64 empty optional-interval cases and68 nested empty-reference
cases. There are no other pattern summaries. The C diagnostic remains unchanged
in meaning and exits1; its observations are preserved in build/bre/system-reference.log.

scripts/test-bre-reference.mjs independently checks all binary inputs length0..8
for those families:1,533 arithmetic decompositions, each executed by native and
own-chain WASM. It does not derive expected captures from either implementation.
For the first family an initial a-run of lengthr gives whole2*floor(r/2), first
group floor(r/2), second group empty. For the second, the initial a-run is the
whole/capture, including an empty participation at r=0. For the third, enumerate
an outer endpointn and final inner/reference lengthx: the last group must be
a^x followed by b*, with another a^x at n. Prefixes belong to (a*b*)*. Choose
longest whole n+x, then longest outer extentn; the final spans follow from that
decomposition and earlier-iteration priority. A final optional empty iteration
cannot replace earlier participation. All1,533 vectors pass both implementations.

The integrated reference gate runs the raw diagnostic, displays/records its
nonzero result, rejects any unreviewed differing family, and on this macOS checks
the exact31/64/68 totals. This separates a proved selected-profile expectation
from a system-compatibility observation. It does not change failing output into
an implementation expectation or claim universal POSIX/locale conformance.
